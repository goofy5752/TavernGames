# Engine contract for the parallel engine tracks (Сантасе, Белот, Табла, Холдем)

Binding for every engine written in parallel. Written 2026-11-21 by the controller. The session/fairness/UI integration of each game comes later (stages B–E); these tracks build **only the pure engine + its tests** (and Belot's parity tooling), so the integration can plug them in unchanged.

## Base contract (stage 1, see `engines/tictactoe.lua`)
- File `engines/<id>.lua`, starts `local _, ns = ...; ns.Engines = ns.Engines or {}`; `local E = { id = "<id>", minSeats = n, maxSeats = m, ... }; ns.Engines.<id> = E`; ends `return E`.
- Pure Lua 5.1: no WoW API, no globals, no `bit`, no `math.random`/`math.randomseed`, no `os.*`. Deterministic from input. Integer arithmetic only where it matters (`%`, `math.floor`).
- `E.new(opts) -> state`; `E.apply(state, seat, action) -> true | nil, reason` mutates `state` in place and must leave `state` untouched when it rejects; `seat == 0` = the table (system actions). `E.legal(state, seat) -> {action,...}` (every legal action for that seat now; `{}` if none). `E.auto(state, seat, random) -> action|nil` (a legal action for the seat on turn, nil off-turn; `random(lo,hi)` may be used, never `math.random`). `E.system(state) -> action, delaySeconds | nil` (what the table does next: deal, next hand, ...; the host applies it at seat 0). `E.snapshot(state) -> table` / `E.restore(table) -> state` (plain-data deep copies; snapshot must contain only strings/numbers/booleans/tables, no functions, no cycles).
- Actions are small plain tables `{k = "<verb>", ...}` with short keys (they go over the wire).
- Stage A optional fields you must provide: `E.options` (array of `{id, choices = {...}, default}`; chosen values reach `E.new` as `opts.opt`), `E.new(opts)` also gets `opts.first` (starting seat) and `opts.seats` (array of booleans, occupied at start), `E.result(state) -> nil | {winners = {seat,...}, losers = {seat,...}}` once the **match** has ended, `E.over(state)`, `E.leave(state, seat)` (a seated player left while live: must not fail; for 2-player games and Belot this ends the match with the leaver's side as losers; Hold'em folds them and removes them after the hand), `E.start` (`"host"` for Hold'em only; others start when every seat is filled).
- Rejection reasons are short strings: `"seat"`, `"turn"`, `"phase"`, `"action"`, `"card"`, `"move"`, `"amount"`, ...

## Cards (Сантасе, Белот, Холдем)
- Card face = 2-char string: rank `2 3 4 5 6 7 8 9 T J Q K A` + suit `C D H S` (♣ ♦ ♥ ♠). E.g. `"TS"` = 10♠, `"9H"`.
- **Cards are tracked by deck index.** A hand starts with the system action `{k = "deal", deck = {face1, ..., faceN}}` — the full shuffled deck order (it will come from the commit-reveal shuffle; tests pass fixed decks). The engine stores `state.deck[i]` (face) and keeps every hand, pile, stock, trick, board as **arrays of deck indices**. Dealing order is fixed by the engine (document it at the top of the file; for Belot it must match BelotGameEngine's dealing so parity fixtures line up).
- `E.view(state, seat) -> state'`: deep copy in which every `deck[i]` the seat may not see is `nil` (indices and array lengths unchanged). `seat` 0/nil = a watcher. Visible = own hand, cards on the table, taken tricks if the rules let players look (Сантасе: no, only the last trick; Белот: only the last trick), face-up trump, community cards, showdown cards, everything at match end. The undealt part of the deal action is never visible.
- `E.apply` must work **both on the full state and on any `E.view(...)` of it**:
  - A play action carries both index and face: `{k = "play", i = <deck index>, c = <face>}`. On a view where `deck[i]` is nil it sets `deck[i] = c`; where known it rejects a mismatch (`"card"`).
  - A rule that needs hidden information (e.g. "must follow suit" for an opponent whose hand is unknown) is checked only when every needed face is known; otherwise skipped. The full replay after the seeds are revealed (stage B) re-runs every action on the full state and flags the hand if anything was illegal — so the full-state check must be complete and strict.
  - `{k = "show", cards = {[i] = face, ...}}` at seat 0 fills faces on a view (used for: my own dealt cards, my drawn card, face-up trump, flop/turn/river, showdown, last trick). On the full state it is a no-op if the faces match, else rejected.
  - `E.legal`/`E.auto` for a seat must use only what `E.view(state, seat)` shows (bots and timeouts run on views).
- Provide `E.hidden(state, seat) -> {i, ...}`: deck indices the seat holds that the others cannot see (used later to verify "every played card was in the player's hand").

## Dice (Табла)
- Dice come as a system action `{k = "dice", d = {a, b}}` (1..6 each; produced later by commit-reveal; tests pass fixed values). No hidden information: the engine has **no `E.view`** (amended by Addendum 6: an engine without `view` is an open game; the old "still provide it" no longer holds).
- A full turn is one action `{k = "move", steps = {{from, to}, ...}}`; partial staging („Върни“/„Готово“) is a UI concern. `E.legal` returns every distinct legal full move (dedupe by resulting position), respecting: use both dice when possible; if only one can be used and either could, the larger; doubles = 4 moves; no legal move → the only legal action is `{k = "move", steps = {}}`.

## Addendum
- Every card engine exposes `E.DECK`: the canonical unshuffled face list (Сантасе 24, Белот 32, Холдем 52). The fairness layer will produce a permutation `p` of `1..#E.DECK` and the deal action carries `deck[i] = E.DECK[p[i]]`.
- Each track writes a rule table at the top of its engine file (short, numbered rules, the exact numbers) — this is what reviewers check the code and tests against, and what the rules book will later be written from.

## Addendum 2 (stage B, fairness integration)
- **Randomness marker `need`.** `E.system(state)` returns the action `{k = "deal", need = "deck"}` (card engines) or `{k = "dice", need = "dice", ...}` (Табла) when the table must supply randomness. The session never applies such an action itself: it asks the extensions (`need` hook), and whoever supplies the payload (`deck = {...}`, or `d = {a, b}`) applies the same action **without** `need`. `E.apply` rejects an action still carrying `need` with `"need"`.
- **view + deck.** `E.view(state, seat)` changes nothing but `deck` (faces the seat may not see are `nil`) and sets `full = false`. A copy of any view that has the whole deck and `full = true` must behave exactly as the full state (this is how `Fair.audit` replays a hand once the seeds are revealed). `{k="deal"}` on a view accepts no deck or any subset of the faces; on a state with `full == true` it accepts only a complete permutation of `E.DECK`.
- **`{k = "void"}` at seat 0.** While a hand runs: annul it (nothing scores) and go back to the phase in which `E.system` asks for the deal; in any other phase reject with `"phase"`. Used when the dealer lost the deck (reload) or stood up mid-hand.
- **`E.again`.** `true`: once the match is over (`E.over`), the host may start a new one with `client:startGame()`; the previous loser leads (`E.nextFirst`).
- **`E.auto`/`E.legal` on unknown faces.** They return nothing for a hand whose faces the view does not show (bots and timeouts run on views).
- Extension hooks run under `pcall` in the session (an error is logged and counts as `nil`; re-raised only with `env.strictHooks`, tests): `act`, `applied`, `auto`, `adopted`, `hostChanged`, `need`, `table`, `snap`.
- `SNP.fr` for card games: always present, `{n}` when no round is open, else `{h, d, p, c, st, n}` with `p` the occupied seats strictly ascending.

## Addendum 3 (stage B final fix wave, 2026-11-21)

Nothing here changes an engine's rules or the `E.*` functions; it changes what the fairness extension (`core/Deal.lua`) and the session do around them. Engines written against Addendum 2 need no edit.

- **`{k = "void"}` and the dealer (ruling PB6 changed).** The engine's side is unchanged: the hand is annulled, nothing scores, the engine goes back to the phase in which `E.system` asks for the deal and keeps its own notion of who deals/leads. The fairness dealer (who holds the deck) is no longer the same seat again: the count of deals `n` is not taken back, so the next deal is made by `p[(n + 1) % #p + 1]` with the old `n + 1`, i.e. the next seat. An engine must therefore not assume that the seat that supplied a voided deck supplies the next one.
- **Dealer of a round, restated.** `n` = deals made in this match (not hands completed). Shuffling (`st` = `commit`/`seed`): `d = p[(n + 1) % #p + 1]`. Dealt (`st` = `dealt`/`done`): `d = p[n % #p + 1]` (the same formula with `n - 1`). `SNP.fr` is checked against this on adoption.
- **Public faces only.** The host applies a dealer's `deal`/`show` request on a copy of its state and refuses it when a face in it is not in `E.view(state_after, 0).deck`. So `E.view(state, 0)` must show, right after a deal or a show is applied, every face that deal or show is allowed to publish (the turned-up trump, shown marriage partners, the whole deck once the match is over), and nothing else.
- **`SNP.fr` is validated like `open`.** A round arriving in a snapshot must fit: integers `h`, `d`, `n >= 0`; `p` strictly ascending seats of the table, at least two; `h` not above the snapshot's `q`; the dealer as above; for a round new to the member, from the host it knows: `h` above every round it has seen and events in between, and while shuffling every seat of `p` occupied and the member itself in `p` unless it just sat down. A round that does not fit is dropped (no round; a deal on it closes `"bad", "commit"`). An `open` event must carry `h = seq + 1`.
- **Commits are held.** The first commit a client sees for a seat in a round (event or snapshot) is kept for the round and the audit checks the revealed seeds against those. Another value later is a foul. The commit under a client's own seat must be the commit of its own seed (a client that logged in again mid-round cannot know and accepts what the snapshot shows); the seed revealed for the seat it committed at must be its own seed.
- **Fouls and new reasons of `"bad"`.** A foul noted against a round decides its verdict however the round ends (reveal, noreveal, void, replaced by a new open). Reasons now: `seeds`, `commit`, `deal`, `dealt`, `play`, `noreveal` (as before) plus
  - `mine`: my commit or my seed was replaced;
  - `round`: a snapshot changed my round (participants, dealer), dropped or ended it at the very event I am at, or was pushed on me unasked and skipped events of a hand I held whole;
  - `forged`: an event for my seat that I did not send (engines with `view` only: there the host never moves for another seat and a timeout is played by the seat's own client), or a void in my name while I hold the deck and my seat;
  - `nodeal`: a shuffle that had every commit was opened again although nobody left: the dealer had the seeds and did not deal within `FAIR_WAIT`. Not on a client that knows better (a participant that never sent its seed; a dealer that lacked a seed or whose deal request was lost): those close it `"unseen"`. The same dealer deals the reopened round.
  - `play` also covers an event of the host that the member's engine refused during a hand it had seen whole.
- **`"unseen"` needs a reason.** It is the verdict only when the client came or logged in again mid-hand, the host changed, or the client asked for the snapshot (`SYN`, `WAT`, `SIT`) after losing events. Even then the audit checks the seeds against the held commits and every face the client was shown or sees against the revealed deck (`"bad"`, `commit`/`seeds`/`dealt`/`deal`); only the replay of the moves is skipped. `Fair.audit` returns `"unseen"` itself when `rec.base` is nil; `rec.faces` = the faces of the client's state.
- **Voids and no-deals are named and counted.** `s.fairVoids[name]` per dealer and match; `s.fairLast.n` on such a verdict; `Deal.status` returns `"fair.voidBy", name` or, from the dealer's second one, `"fair.voidMany", name, n`; `Deal.alarm(s)` (the line is red) is true after a bad hand on my own client or a dealer's second void/no-deal in the match.
- **Complaints.** `ACT {k="fair", op="protest", h, why}` → `EV` seat 0 `{k="fair", op="protest", h, seat, why}`, `why` one of `mine`, `commit`, `round`, `play`, `forged`, `dealt` (sent only for what the cheated client alone can see: a foul, or private faces that are not the deck's), once per seat and hand, for the running round or the last closed one. Every client keeps `s.fairCry = {h, seat, name, why}` (the last one). A complaint is a claim nobody else can verify (any seat can send one, and a host can order one): it changes no verdict, no count and no colour on another client. `Deal.claim(s)` returns `name, why` only while the complaint names the hand the client closed last (`cry.h == fairLast.h`) and comes from another seat; the line shows it after the client's own verdict („… · X твърди, че е нередовна“), amber unless the client's own finding is red, and it is gone when the next hand closes. A complaint under a client's own seat that it did not send (`s.fairSaid[h]` is unset) is somebody speaking in its name: the running round gets the foul `forged`, or the hand it closed last is revised to `"bad", "forged"` (the `"fair"` event is emitted again for that `h`, `fairSeen` recounted), and it tells the table.
- **Hooks.** `adopted(s, prev, m, how)`: `how = {fresh, changed, asked, sat, q}` (a session created by this snapshot; a host or epoch new to me, or I was stale; I asked; I got a seat I did not have; my `seq` before it). New: `refused(s, seat, a)` (member: an event of my host that did not apply), `forged(s, seat, a)` (member, engine with `view`: an event for my seat that I did not send). Both run under `pcall` like the others.
- **New host during a shuffle.** With every commit in, a new host does not open the round again: it waits `FAIR_WAIT` and the dealer asks it for the deal again. With commits still missing it opens again at once, as before.
- **Trace.** `/tavern debug` writes a `PRV` as `cards="<N>"` and a `SED` as `s="<32>"`.

## Addendum 4 (stage C, Белот)

The rules of Belot are unchanged (the 60 parity matches still replay); this adds contract functions and one view rule.

- **`E.dealer(state) -> seat`.** The engine names the dealer of the next round itself, from public data only. Belot: `(state.first + 2) % 4 + 1`, the seat before the one that bids first (first match: 4, then 1, 2, 3, ...). It rotates strictly by seat and depends on nothing a player can influence. A passed-out deal and a void move it on; the no-deal reopen applies no void, so the same dealer deals it. Engines without it keep the count formula of Addendum 3. `dealerFor(s, p, n)` in `core/Deal.lua` takes an optional `n` (used by `fits`).
- **Void and the dealer.** After a void the deal passes on to the next seat (as in Addendum 3). A late void, after the hand has ended, is accepted only if the dealer's seat played no card in that hand (Belot: passed out); otherwise it is a no-reveal.
- **`E.bot(state, seat, random) -> action or nil`.** A bot asks it first (on its view); `nil` falls back to `E.auto`. Belot bids suits only, never Без коз, Всичко коз, контра or реконтра; `E.BOT_BID = 34`, `E.BOT_LUCK = 6`; the fourth to speak never passes a deal out. Bot tables fill with idle bots whenever the table is not live.
- **`E.announce(state, seat) -> {k="ann", a} or nil`.** Everything the seat on turn may still announce as one action (a four before a sequence through it). `nil` off turn, once announcing is closed, with nothing to announce, or on a view that does not show the hand.
- **`E.auto` plays the lowest card.** In the auction a pass; in the tricks first `E.announce`, then the lowest legal card (fewest card points under the contract, a plain card before a trump), with the belote when it is one. Nobody acts for an offline player: after `OFFLINE_STAND_SECONDS = 180` he is stood up, the match ends and his team loses.
- **Belot's view keeps the played cards.** During the play `E.view` shows every card that is in no hand (all cards played in this deal) besides the seat's own hand, so a member that logs in again after an announce does not resync. This is the one change to what a Belot view contains.
- **PC1 amends PB8 for Belot.** `E.nextFirst(prev, occupied) = prev.first % 4 + 1` (when that seat is occupied): the deal keeps rotating across matches; the previous loser does not lead. Other engines keep PB8 (the loser leads).
- **`"result"`** carries `left` (the seat whose leaving ended the game) and `names` (seat -> name or `false`). `E.leave` ends the match at once for the leaver's team; `winners = {w, w + 2}`, `losers = {3 - w, 5 - w}`.

## Addendum 5 (stage C final fix wave, 2026-11-22)

Rulings of the stage C final review. One rule of Belot's score changes (the announce check); the rest is around the engines.

- **Announces and belotes are checked when the deal is scored (Belot; amends "stage C changes no rule of the score").** A view cannot check another seat's announce when it is made, so it is taken on trust then. At the seat-0 `{k="score"}` every card has been played face up: `E.apply` checks every entry of `state.ann` against the eight cards dealt to its seat (deck indices `seat, seat + 4, ...`), on a view and on the full state alike. An announce must be one those cards offer (the offered list of rule 9: a longer run is one announce) with no card in two announces of the seat; a belote needs the other of K/Q among the seat's eight. One that fails gets `v = 0`, `on = false`, `bad = true` in `res.ann`, takes no part in the comparison of rule 10 (it cancels nothing) and scores nothing. `{k="score"}` is refused `"show"` while a face of an announcing seat is unknown. The full state never holds a failing announce (`applyAnn` refuses it), so the 60 parity matches are unaffected. On a view a play with `b = true` is refused `"belot"` when the other card is known to be outside that hand.
- **`E.foul(state) -> seat or nil` (optional).** The seat the engine caught cheating in the hand just scored, from public data (Belot: the first `bad` announce of `res.ann`), between that hand's score and the next deal; `nil` otherwise. The fairness layer asks it after every event and on adoption while the round is `"dealt"`: the round gets the foul `announce` and closes `"bad", "announce"` on every client (also one that would close `"unseen"`), with `s.fairLast.who` = the player's name; `Deal.status` returns `"fair.announce", name`; the `"fair"` event carries `who`. `announce` is not a private reason: nobody complains of it (no `protest`).
- **`E.teams` (optional, `true` for Belot).** A seat that leaves loses the match for its partner too; the table frame asks before „Стани“ in a live match of such an engine.
- **The dealer keeps its round across a `/reload` (amends "seeds, decks and private faces are never in SavedVariables").** Once the deck is made the dealer writes `env.db.fairKeep = {tid, h, seat, me, seed, seeds, deck}` (`core/DealKeep.lua`; per character in the WoW adapter). A client that comes back by a snapshot as the dealer of that table, hand and seat under the same name, with every kept seed matching the commit the snapshot shows, takes the round up again: in a shuffle it asks for the deal again, in a dealt hand it sends every seat its faces again and the hand goes on. No void, no count against the dealer. The dealer itself closes that hand `"unseen"` (it did not watch it whole); everybody else audits it as usual. The record is dropped when its round closes (reveal, void, no-reveal), at a start or an abort of that table, when it does not fit the round it is asked for, and it is replaced by the next deal the client makes. It is never in a message and never in the trace.
- **A void is the fallback.** Only a dealer that cannot restore (a crash, another computer) asks for the void; the request is repeated every `FAIR_ASK_GAP` while the hand runs and the deck is gone (12 times at most). The rules of Addendum 3 and 4 then apply unchanged (counted, named, the deal passes on).
- **No void once the engine's next step is its own.** The host refuses a dealer's void request while `E.system(state)` returns an action without `need` (Belot: phase `"score"`, the eight tricks are played). That deal is scored; a dealer without its deck then cannot reveal and the hand closes `"bad", "noreveal"`. `E.apply` itself still accepts `{k="void"}` in `"score"` (the engine's rule is unchanged).
- **The automatic move is retried.** `Session:armAuto` (engines with `view`): after the deadline my client makes its automatic move again every 5 s, 36 times at most, while the table still stands at that event (a duplicate is refused `"turn"` by the host). When there is no move to make it calls the new hook `stuck(s)`; the fair extension then asks the dealer for missing faces at once (`PRQ`). The host's own seat is retried the same way (armed from the fair extension's `applied`); its first move at the deadline stays the turn timer's.
- **Hooks.** New: `stuck(s)` (under `pcall` like the others).

## Addendum 6 (stage D, Табла: dice by commit-reveal, `core/Dice.lua`, `core/DiceMember.lua`, `core/DiceCheck.lua` and `core/DiceLine.lua`)

Nothing here changes an engine. It is the contract of the extension `dice` (`ns.Ext.dice`, `ns.Dice`), which answers `{k="dice", need="dice"}` with a throw. No dealer, no private faces, no audit: a throw is three ordered seat-0 events and every client derives the dice itself.

- **An open game: no `E.view` (Табла).** "Has `view`" stays the one marker of hidden information in `core/Session.lua`, `core/Lifecycle.lua` and `core/Member.lua`. An engine without it is an open game: every client holds the whole state, snapshots are whole, and:
  - the host's turn timer plays `E.auto` for whichever seat is on turn, online or not (the first legal full move; no automatic loss). That is the one automatic move per deadline: the automatic-move retry of Addendum 5 (`armAuto`, every `AUTO_RETRY` seconds) is view-only, so an open game gets none;
  - the forged-move check of `core/Member.lua` (a host event for my seat that I did not send, `view`-only) does not run: the host may move for either seat of an open game and the guest sees it on its own board, as in Морски шах. Accepted risk F8;
  - the snapshot state is `engine.snapshot(state)` in full; a member that logs in again is judged by the proofs below, not by what its view lacks.
- **`E.stage(state, seat, steps) -> {pts, pin, bar, off, left, next, done} | nil`.** Табла: the position after a partial move (the UI's „Върни“/„Готово“ is a UI concern; only `{k="move"}` with the whole move travels). `next` = every single step that may follow, computed even when the steps are already `done` (a move that ends legally may still be continued: with 5-1, 4/0 ends where 4/3 3/0 ends, and 3/2 may follow); `done` = `E.apply` accepts the steps as the whole move; `nil` when the steps cannot begin a legal move or it is not the seat's turn.
- **`E.again` without `E.nextFirst`.** The host may start a new match with `client:startGame()`; it begins again with Обикновена (game 1) and the opening throw: no "the loser starts". The variant is never an option: it is derived from the game index, `E.VARIANTS[(game - 1) % 3 + 1]` (Обикновена, Тапа, Гюлбара), by the engine and by `E.thrown`.
- **A seat-0 `{k="dice"}` is applied by the extension, never sent.** The extension derives the dice from the seeds and applies the action locally on every client; no message carries a dice value. A seat-0 `{k="dice"}` event from a host is applied (the host is authoritative) and flagged `"bad", "forged"`.
- **The throw.**
  1. Throw `h` is opened by the host with the event number it gets (`h = seq + 1`); its `rollId` is `Fair.handId(tid, h)` = `tid .. "/" .. h`.
  2. The opener is the host's seat `d`; the other seat is `g = 3 - d`. The open event carries the commit of the opener's seed (`EV {k="throw", op="open", h, c}`). `g` commits a fresh seed (`ACT` op `commit` -> `EV {..., op="commit", h, seat = g, c}`), sees its own commit come back as an event and whispers its seed to the host (`ACT` op `seed`, never relayed as it is). Until then the opener's seed has not left the opener's client, so `g` reveals blind.
  3. The host publishes both seeds in one event (`EV {..., op="seeds", h, s = {[seat] = seed}}`). Every client checks both against the commits and applies the dice `Fair.dice({seed_1, seed_2}, rollId)` (seeds in seat order) itself as the engine's `{k="dice", d = {x, y}}` at seat 0. No message carries a dice value.
  4. `DICE_WAIT` seconds after the open without `g`'s seed, the host publishes its own seed alone and the dice are `Fair.dice({seed_d}, rollId)`: the silent seat has lost its say over that throw. A throw is never opened again for the same host (`need` re-arms the wait of a running throw; only an explicit `Dice.open` opens over one); a new `h` exists only after a host change. A host whose wait runs out while it holds no running throw at all opens one.
  5. `g` says its last throw action again (the commit, or the seed once its own commit is in) every 3 s while the throw runs, twice at most per throw; the host ignores a second commit and a seed after the close.
- **Seeds (final review I4; amends stage B's "Seed = `SEED_BYTES` values of `env.random(0, 255)`").** A seed is never the generator's own output: every seed is published sooner or later (one per throw here), and a run of outputs of a weak generator would give the next seed away to the host before it commits (`math.random` on Forever is not measured). `Fair.seed(env, purpose)`: each client builds a secret pool once, at its first seed, = SHA-256 of `env.me`, `env.guid`, `env.now()`, `env.epoch()`, 64 values of `env.random(0, 255)` and `env.entropy()` (optional env call -> string; the WoW adapter gives `GetTime`, `GetServerTime`, `debugprofilestop` and `GetFramerate` where the client has them, and the address of a fresh table). A seed is the first `2 * SEED_BYTES` hex characters of SHA-256(`pool | counter | purpose`), `purpose` = `"deal|" .. handId` for a card round and `"dice|" .. rollId` for a throw; the format (32 lowercase hex) and the commit are unchanged. The pool is kept inside `core/Fair.lua` by env (a weak table): in no message, no trace line, no saved variable, no field of the client. The test sim's clients make plain seeds (16 values of their `env.random`) so a test can say what a seed is; `env.realSeeds = true` gives the real ones.
- **The seats of a throw (final review C1).** `Session:apply` refuses a seat-0 `sit` onto a seat that is not free, in every game (an honest host never sends one: `Session:check` answers `"taken"`); on a dice table the refused event is `forged` (see **Live events**). A seat can still be emptied and filled again by events, so on a seated member an `open` whose opener seat is my own seat number, or that comes while my seat bears another name than mine, is the foul `forged`: I never opened it. I take no part in such a throw and it closes `"bad"`.
- **Verdicts** of a closed throw: `"ok"` (both seeds), `"alone"` (the opener's only), `"unseen"` (both seeds, but I logged in again mid-throw without my seed and could not check the commit under my seat, or the throw was already open when I came, see **A match I walk into**; never `"ok"`), `"bad"` with a reason:
  - `mine`: the commit under my seat (event or snapshot) is not the one I sent; I then send no seed. Seen by `g` alone; everybody else closes that throw `"ok"`.
  - `commit`: a snapshot changed the opener's commit of the throw I hold.
  - `dodge`: a throw of mine that was not done was opened again (an `open` event over it) after I had sent my seed; or a snapshot nobody asked for (`not how.asked`) from my own host dropped it or replaced it by another number after I had sent my commit or seed; or its opener raised its own epoch over it while it ran (a `TBL`, `TCK` or snapshot of the same host under a higher epoch: an honest host never does that), on every client that sees it.
  - `forged`: a throw opened under my own seat or while my seat bears another name (**The seats of a throw**); a seat-0 `{k="dice"}` event. Dice come only out of a throw; the event is still applied (the host has those dice), and every client flags it with `h` = that event's number. Also, on a member: the table is not the one the throws gave (see **A state that is not mine**); the last throw the member closed is then closed again as `"bad", "forged"` whatever it was (counted once, as what it is now; no later snapshot turns it back), and the member complains.

  A foul (`throw.foul`, the first one wins) decides the verdict however the throw ends (seeds, replaced, dropped).
- **Unheard.** `s.diceUnheard` counts, on `g`'s client, the throws its host made alone although it had sent its commit or its seed, the throws it had sent them to that were gone from a snapshot it had asked for (it missed events and cannot judge), and the throws it had sent them to that died with a host that really changed (another player hosts now). One can be an honest loss; from the second one in a match the line is red.
- **My own loading screen (final review I2).** The env contract gains two plain fields that only my own client sets: `env.loading` (true while the client shows a loading screen) and `env.loadedAt` (`env.now()` when the last one ended). The WoW adapter sets them on `LOADING_SCREEN_ENABLED`/`LOADING_SCREEN_DISABLED` and on `PLAYER_LEAVING_WORLD`/`PLAYER_ENTERING_WORLD` (an event the client does not know is not registered). Whenever a throw would be counted as unheard (every case above), my client first asks whether it was away: it shows a loading screen now, or one ended less than `DICE_WAIT` ago (the host's wait overlapped it); in a snapshot that resyncs me also one that ended after the last event or snapshot I heard (`s.diceHeard`: the messages in between were lost), provided the snapshot comes within `DICE_WAIT + PING_EVERY + SYN_MIN_GAP` seconds of its end (the time an honest host's tick and my request take). Then the throw is counted in `s.diceAway` instead: a neutral tooltip line (`dice.away`), nobody is blamed. **One loading screen excuses one throw** (`s.diceAwayAt` = the `env.loadedAt` of the screen whose excuse is used, `true` while it still shows): every further throw under the same screen is unheard like any other (re-review Important 1). The verdict of the throw itself is unchanged (`"alone"`, amber), and **a snapshot that brings the dice of a throw I did not see close always closes that throw `"unseen"` on my line** (amber; unless it was closed `bad` there), whatever was counted: the line never stays green across a resync, and only a throw I then see whole turns it green again. A loading screen that was over before the events of the throw reached me excuses nothing. What this leaves: per loading screen of mine, one throw made without me is not counted against the host; it shows amber (thrown alone, or unseen).
- **A match I walk into (final review I1).** `Member.adopt` tells the hooks `how.req`: the snapshot takes me in at my own SIT or WAT for that very table (a newcomer; not a login back to a seat I held while a request for another table was pending, not a snapshot of the table I am at). The same holds for a snapshot that brings a running match over a table that had no match yet on my client (my state was nil and I did not just log in): a host cannot answer my SIT with an open table and push the match afterwards. When such a snapshot shows a live match that is not over, nothing thrown so far was witnessed by me: unless the proof is the very one I hold from my records, the dice of the board are closed at once as `"unseen"` (number = the proof's, else the snapshot's `q`; the line is amber „не съм видял цялото хвърляне“), and a throw that is already open in `SNP.fr` is taken with `late = true` and closes `"unseen"` as well (I still give my part if I am `g`). The first throw I see from its `open` event is the first that can be `"ok"`. This closes the case of a host that ends its table, announces another and answers my SIT there with a running match and dice of its own making. A snapshot that fails the proof checks is `forged` as before; a table that has not started and a login back to my seat are unchanged.
- **Dice are proved, not believed; nothing the host can set is taken on its word.** Every client keeps the proof of the last throw it saw closed, `s.diceProof = {h, c = {[seat] = commit}, s = {[seat] = seed}, r, t}` (the seeds event's list: one seed for an alone throw; `r` = the seat the throw was for and `t` = that seat's roll number in the game, both as the client's own state has them after the dice, `E.thrown`; neither in an opening throw; reset at `start`), and a snapshot always carries the host's: `SNP.fr.p` (beside `h, d, c` of a throw still running; `fr` is absent only with neither). A member that adopts ANY snapshot (asked for or not, behind or not, under a raised epoch, after a login, from a new host, after the table ended under it) checks it; what fails is `"bad", "forged"` on its client, with a complaint:
  - the state must be one that throws give: the engine's optional `E.thrown(state, prev) -> false | moves, roller, number`. Табла: the variant is the one of the game index (rule 1; the engine has no variant option, so `var` is derived, never read), each seat's `rolls` is a count and 0 while the game has no dice; a turn is one move action, so outside phase `move` nothing is open; in it `left` is the two dice, four of a double, or in a cascade four of the number `cv` from the double up, fewer only as a transferred remainder; a cascade only in Гюлбара and only when the roller's `rolls` have reached `CASCADE_ROLL`. `moves` = the move actions the state says were made since the throw (one for every number a cascade went on, one more for a handed-over remainder; else 0); `roller, number` = in a turn, the seat that threw for it (the other seat when a remainder was handed over) and its roll number;
  - a state with `dice` or open steps (`left`) needs a proof whose every seed opens its commit (`h` an integer not above the snapshot's `q`); `state.dice` must be `Fair.dice` of the proof's seeds in seat order under `tid/h`; a turn in progress must be the proof's (`roller == p.r`, `number == p.t`), so a throw cannot be given to the other seat or to another turn; `moves` may not exceed the snapshot's own events since the throw (`q - h - 1`: `q` can only convict, it excuses nothing);
  - with records of the table (see **My records outlive the session**) and the proof being the very one I hold: no dice came since, so the roll counts must be my own state's (`E.thrown` with `prev` = my state: equal in the same game; another game only without dice yet, whoever hosts). Under the host I knew, steps open again after my state saw that turn end (a turn played twice), a cascade behind mine, or one further on than the events that host says I missed are forged. Any other open steps that are not mine (a cascade number I did not see played, also from another host) cannot be vouched for by anything I received: they are counted like a throw I did not see (below);
  - with records and another proof: a seed under my own seat (unless I had stood up myself meanwhile) must go with a commit I made for that very throw and for that seat's turn (`s.diceOwn["h:commit"] = r` as I saw it when I committed; 0 in an opening throw), whoever hosts now and whatever was hosted in between; the throw I hold (same number, same seeds) told otherwise is forged;
  - under the host I knew (same player as before, `s.diceHost`; not when another player hosts now, `s.diceNew`: that table may honestly be behind mine or beside it): a proof that is not the one I hold must be of a later throw, and at my own event number and epoch the whole state must equal mine (`engine.snapshot` of both).
  A valid proof is taken over as the member's own. The last throw the member closed (or the proved one) is closed again as `"bad", "forged"` whatever it was (counted once, as what it is now); no later snapshot turns it back.
- **A valid proof and events I missed.** With records of the table:
  - the proof is of the running throw I hold (its seeds event never reached me): the throw is finished from the proof exactly as from its seeds event, **on my own state** (`"ok"`; `"alone"` and unheard when the seed is the opener's only; the fouls `commit`/`mine` when its commits are not the ones I hold). The proof I keep gets `r, t` from my state with those dice, and that state is what the snapshot is then held against, so the snapshot's own `r, t` and roll counts must be the derived ones;
  - otherwise, on a seated client, a proof that is not the one I hold is a throw I did not see close, and open steps I cannot vouch for (above) are steps I did not see played. Neither is ever passed over: `"bad", "dodge"` when the snapshot was pushed on me (whoever hosts, also a host that takes the table back from me) or came under an epoch my own host raised; unheard in a snapshot I asked for (also beside a running throw whose number I pass over as old). A running throw I had said my part to and that is gone is counted instead, as above, not twice.
- **My records outlive the session** (`core/DiceCheck.lua`). `client.dice[tid]` = every dice field of the session (below) with my state and event number, written after each of the extension's hooks; it lives as long as the client does (a `/reload` or a login starts without it), except that a record of a table that is no longer listed is dropped `DICE_KEEP = 600` seconds after I was last there (`rec.at`), when the first record of another dice table is written; `presence.been[tid]` goes with it, so a late unasked snapshot of that table is refused with `STD` instead of being taken as a login. Only a login without a record is new to the table (`how.fresh` as the hooks below see it). A `start` or an `abort` while the match was still running on my client is nothing an honest host orders (a match ends first, also by a player leaving, `E.leave`): a running throw I had given my seed to is closed `"bad", "dodge"` (or its foul) before it is dropped, and such a `start` wipes none of the match's counts (`diceSeen`, `diceBad`, `diceAlone`, `diceUnheard`, `diceAway`). ## Addendum 7 (stage E, Холдем: the sealed deal, `core/Book.lua`, `core/BookKeys.lua`, `core/BookCheck.lua` and `core/Cash.lua`)

- **Files and extension.** The extension `cash` (`engine.ext = {"fair", "cash"}`) is `core/Cash.lua`; the book is `core/Book.lua` (the key, the seeds, the records, the live-hand mark of rule 6a), `core/BookKeys.lua` (keys, the close, publishing; it wraps `Session.onStand` so that a stand sends the leaver's key first, with no line added to `core/Session.lua`) and `core/BookCheck.lua` (the check, the end of a closed book, the status line and its tooltip). Every number and shape of the stage is in the stage E plan (Global Constraints, Tasks 1-5) and the stage 1 plan's „Stage E additions“.
- **The eight rules of the sealed deal** (an engine with `E.sealed = true`), as built:
  1. *Who.* The participants of a round are `E.players(state)`, not the occupied seats; the dealer is `E.dealer(state)`: the button, or the next participant when the button's seat has left the hand.
  2. *Key and seeds.* One table key per seated client per sitting (`Fair.seed`), in `env.db.bookKeep = {tid, me, key, g, h}` (`h`: rule 6a; survives a `/reload`; in no message before it is published, never in the trace; **this amends „never in SavedVariables“ once more, beside `fairKeep`**). `Book.key` takes a kept key only for the running game and never one already published. A key I have sent is recorded by `Book.spend` in `env.db.bookSpent` before it is sent, and **never deals again** (`Book.key` never gives it; a later hand gets a new key) whatever the host or `state.g` says. It may be *sent* again, by design: once after a final keys event that lacks it (`book.resent`), once after a snapshot of the game over (`book.synced`), after a host change, and after a `/reload` from `bookKeep`. Hand `h`'s seed is `Fair.handSeed(key, handId)`; the commit of a hand is the commit of that seed.
  3. *One commit event.* The host publishes the commits together as `{k="fair", op="commits"}` once every participant's is in.
  4. *The dealer deals every street* (`need = "faces"`). The dealer asks the host for the step (`ACT {k="book", op="step"}`), and **a dealer step needs every face**: the host applies the step to a trial state and refuses it if any face the street deals is missing (`Book.faceless`), and publishes only faces a watcher may then see. A member does not refuse: it applies the host's street event and, if a face of the street is missing, notes the foul `deal` on the round (only a modified host plays such an event).
  5. *No reveal.* When the hand ends every client writes the hand's record and closes the round `"sealed"`; a voided hand is recorded too (`Book.seal` before the void close; closed once).
  6. *Keys.* A key travels in an `ACT {k="book", op="key"}` that **carries `g`**, the game's identity; a key whose `g` is not the running book's is refused without a foul and does not block the new game's key (it can arrive after „Нова игра“). The keys event is `{k="book", op="keys", m, g, f}`. **Only a final publish (`f = true`) of a game that is over ends the book** (closes it, ends the wait, consumes a member's resend); earlier keys events (a leaver's, the early close on a stand) are partial. (A host that stands up while the game runs publishes its own key with `f = true` as well; the game is not over, so members do not close on it.) A stand while `E.over` first publishes `book.wait`, the leaver's key included. The host publishes when every seated seat's key is in, at the latest `BOOK_WAIT = 30` s **after the game is over** (`E.over` reached on the host, `book.overAt`), not after the „Приключи“ press: the hand running at the press is played out first, however long it takes, and the members' keys can only leave after it. A late key goes in a further keys event and the final book takes it.
  6a. *My live hand (the final review's I2).* A member's key, with the other participants', gives the deck of every hand it committed a seed to. So a member sends its key at the game's end only when it saw the hand it committed to last **end event by event**. `client.bookHot = {tid, g, n}` (and `bookKeep.h = n`, `n = state.hand`) is set when my seed of the running hand is taken (`Book.seedFor` -> `Book.heat`) and dropped only by an applied event that ends hand `n` on a state where it was running (`book.ran`; `Book.watch`), or when I stand up myself (my key is published then anyway). No snapshot drops it; a later hand I commit to replaces it (also one a snapshot brought me into). If the game is over while it is still set (the end of my hand reached me only by a snapshot: a snapshot that says „closed“, or one that says „hand done“ followed by a `close` event), **my key stays** (`book.held`) and my book is marked forged (red, one bad hand). When the same game then runs on (the true snapshot), the hold is lifted and my key goes at the real end. After a `/reload` nothing is left in memory; `bookKeep.h` is: a first snapshot that shows hand `h` still running makes it hot again, one whose hand count shows it ended (`state.hand > h`, or `= h` and no hand running) is believed and the key goes; one behind `h` is not. The mark lives on the client, not the session, so an `END` followed by a snapshot does not shed it. Second, detection: my key left because the game was over (`book.done`) and the same game `g` runs again under the same host: forged (red); `book.sent`/`book.out` are cleared so that the key of my later hands goes at the real end. `book.done` is the name of the host my key went to; only a host of another name clears it (a claimant that was behind me is not a liar), never the same host under a new epoch. What this does not close is residual 8. An honest client pays for it in one rare case: it loses the events that end its last hand of the game and heals by snapshot (the snapshot overtakes the hand's last event, or the host crashed while sending it and the claimant's snapshot ends the hand): its key stays, its own line turns red, and the others read its hands as unverified, by name.
  7. *The check.* A hand is checked as soon as every participant has a published key (`q >= h`) whose seed gives the held commit; every recorded face must be the deck's.
  8. *What this leaves (accepted).* The dealer who stands up mid-hand voids the hand and leaves with its chips (stacks are free). The dealer's client holds the deck. A player who vanishes without its key leaves its hands unverified, amber and by name, not red. A hand is readable once all its players have left while the table runs. A player who stands up gets no verdict unless it stays to watch.
- **`E.players`, `E.dealer`, `E.inHand`, `need = "faces"`.** As in rules 1, 4 and the fair layer's use of `E.inHand` (its negation is „the hand is over“). For Hold'em `E.dealer` is public data only (the button) and rotates by seat.
- **`void` for Hold'em.** `{k="void"}` annuls the hand: every chip put in goes back, no pot is paid, the button moves on (the next hand is dealt by the next participant). Its record is checked at the close (rule 5). The dealer's stand-void refund is accepted.
- **`away` / `back`.** `{k="away", seat}` (seat 0) sits a silent seat out (its blind stays as dead money); `{k="back"}` (the seat's own, after its client sees itself away) deals it in again, only after the running hand has ended. A `join` (the host's `sit` of a newcomer) on a chair that is `leaving` is accepted: the leaver's hand is gone at once, its chips are kept for `last.left`, and the fresh stack is seated at the chair when the hand finishes.
- **`close` and `E.over`.** `{k="close"}` (the host's „Приключи“): the running hand is played out, then `E.over` is true; the table stays and „Нова игра“ starts a new game with fresh stacks, new keys and a new book. `Session:canStart` refuses with `"book"` while the table is live and the host's book of the closed game is not published (it reads `s.book.published`, making no book); an aborted table's book is closed and waits for nothing, so a host that took such a table over starts at once; the `start` event runs the old book to its end synchronously on every client.
- **A leaver's uncalled bet.** A seat that stands up mid-hand is folded and its chips in front stay in the pot, except that an uncalled layer paid by that seat alone goes back to it (as for any bettor everyone folded to), whether or not the chair has been taken (gone flag).
- **`E.publicAuto` and `AUTO_GRACE = 7`.** The timeout move (`E.auto`: check if possible, else fold) needs only public data. My own client plays it at my deadline; **the host also plays it for another seat `AUTO_GRACE` s after the deadline**. This amends PB5 and the forged-move rule of Addendum 3 for such an engine: a member does not count that event as forged when its **own** clock (`s.turnAt`, its own `env.now()` when it applied the event that put the seat on turn, plus the table's turn time, ignoring the `left` the host sent) has passed and the action is `E.auto`'s; any other move for my seat that I did not send is forged.
- **Silence rules (Task 3, five rounds).**
  - *Own-clock checks with slack.* Every member check against the host's timing (an `E.auto` event, a void, a commit-stage lapse) uses the member's own clock and accepts `FAIR_WAIT - AUTO_GRACE` (13 s) of lag: the host may act up to 7 s early unflagged.
  - *Seed lapse.* In stage `seed` (every commit in, a seed missing) the dealer names the seats whose seed it lacks (`ACT {k="book", op="missing"}`). The hand is **voided first**, then the dealer and the named seats are played `away`. The **named seats sit out for one hand**: the host records `s.lapseOut` and holds a named seat's `back` until one hand has been dealt without it. A seat never named is not held; the dealer (it is not in `lapseOut`) and the host come back at once, for the next hand; a stage `commit` lapse sits out the silent committers as before.
  - *Amber lapse count.* A void closed in stage `seed` counts in `s.fairLapses[dealer]`, not in `s.fairVoids`, and shows `fair.lapse` in amber on every client; it never raises the alarm. Voids of dealt hands keep the stage B rule (`fair.voidMany`, red).
  - *Release.* The host releases a held seat when no hand can start without it (fewer than two seats can play and no `hand` step is on offer): from the `back` hook and after every event. At three seats the hold depends on the dealer's `back` reaching the host first; if the order is reversed the seat is released early and misses no hand (no lock either way).
  - *Release on promotion.* A held seat that becomes host clears `backAsked` and `lapseOut` and comes back at once (`hostChanged`); a demoted host's stale table is never live (every branch requires `s.role == "host"`). A sit clears the chair's entry.
  - *`hostChanged` arms the step.* The new host waits for an overdue step itself. `dueAt` is cleared only when the step due changed with the host change (a step due only in the new host's snapshot is undated: the wait starts afresh). A step that was already due on the new host's own state keeps its own date: if the old host died at a due step, the new host's `FAIR_WAIT` has long passed by its own clock when it is promoted (about 75 s later), and it voids the hand on the next tick, names the dealer („Ръката е анулирана от ...“, counted in `fairVoids`) and sits it out until its `back`, although the dealer was asking the dead host all along (`tests/core/holdem_table_test.lua` pins this; the cost is accepted, see the final review's M4).
- **`state.g`, the game's identity.** The cash extension writes `state.g = s.seq` (the seq of the game's `start` event) into the engine state at `start` on every client; the engine never reads it, and its copy-based `view`, `snapshot` and `restore` carry it in `SNP.st`. It tells a client which game a snapshot is of (a book of another game is replaced, `Book.of`; a kept key is taken only for its own game; a key message of another game is refused without a foul). It is host-asserted in a snapshot and is never a security check: a key I have sent never deals again by my own spent list (`Book.spend`, `env.db.bookSpent`), whatever `state.g` or the published keys say.
- **The design limit.** Hold'em is a six-seat table with one watcher (`E.maxSeats = 6`, `E.watchers = 1`) and `Session:left()` is sent in whole seconds, the fallback of PE11. Measured: an ordinary hand is 143 whispers (EV 138 + PRV 5) and 22.0-22.5 KB (pinned at 143 and 23 500 B); a full ring with the watcher is 203 whispers and 30.3-31.1 KB (pinned at 203 and 32 500 B); about 25.9 KB without the watcher; six commits about 370 bytes packed, two addon message parts. The plan's earlier figures (about 15 KB an ordinary hand, 192 whispers and about 29 KB a full ring, at most 25 KB without a watcher) were arithmetic from a prototype and are superseded. Nine seats and three watchers (about 73 KB) wait for a later message-budget stage with batched events or a new message type.
- **Residuals, to revisit in the stakes stage** (stage E plays for chips only; with real money each of these needs a ruling):
  1. Host-initiated stands cannot be verified by members: a stand the host plays for a seat is a trusted claim (the Presence check was dropped as a framing risk).
  2. A host that holds a step past `FAIR_WAIT` and then voids is not flagged (a void at or after the wait is accepted; only an earlier one is).
  3. A named seat is held out only by the host that named it (a new host does not know the record), and a re-sit escapes the hold, which is keyed by seat.
  4. A seed lapse that a lying dealer provokes (a deck it already knows) shows only as an amber lapse count.
  5. A member accepts an away of its own seat after 13 s in stage `commit` (the slack above); a seed-stage away of any seat after `FAIR_WAIT` is not flagged.
  6. A host can withhold one player's key, so that hand stays `open` (gold/amber) and an innocent player is named as the one that left no key.
  7. A loading screen excuses one dice throw (stage D, Addendum 6; documented there, cross-reference only).
  8. A modified host can still draw a member's key while its hand is live (rule 6a narrows this, it cannot close it: a member hears of the table only from the host). (a) By events: the host plays the member forged events that end the hand (the others „fold“) and the game; the member sends its key; the host reads the deck and then needs a snapshot to bring the member back, which the member flags (forged, red) after the fact, whatever epoch the host sends it under; a handoff to an accomplice's client is not flagged. (b) After the member's own `/reload` in a hand: the first snapshot is all it has, and one that says the hand and the game ended is believed. Either way one hand per victim per game (the key is spent), and for a hand of more players the host needs every other participant's key by the same trick. A full cure needs a protocol change (for example the members' keys released only against the other participants' signed word that the hand ended).

## Addendum 8 (stage F1, stakes)
- **`E.stakes` (optional, `true` for Морски шах and Death Roll only in F1).** Only such an engine takes a gold stake: `Session.open` refuses `stake` (`"stake"`) for any other game, and `Lobby.valid` does not list a `TBL` whose `sk` is on a game without it (or is not a valid stake, `ns.Stake.valid`). The engine itself never reads the stake: the table carries it (`s.stake`, `TBL.sk`, `SNP.tbl.sk`, `SIT.sk`, `INV.sk`). An engine gets `stakes = true` only once the stage that makes it fair for money (its fouls feeding the debt confirmation) has landed.

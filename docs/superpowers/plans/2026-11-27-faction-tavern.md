# Faction Tavern (Механа на фракцията) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dress the whole addon in the player's faction (Alliance or Horde skin, race decks, hero portraits, coins, parchment ledger, a „Уредено“ toast, quiet game sounds), with every client asset behind an availability check and our own stand-in.

**Architecture:** One registry (`wow/Art.lua`) answers "does the client have this file/atlas/sound" and is the only place that touches client art. `ui/Theme.lua` keeps its token names and gains two skins applied once at login (`Theme.apply`), so most modules re-skin through the tokens they already read. New small UI units (`Decks`, `Silhouette`, `Portrait`, `SettleToast`, `Sounds`) carry the new pictures; our stand-in textures come from one new generator script.

**Tech Stack:** Lua 5.1 (WoW Forever, `## Interface: 16001`), Ace3 subset already in `Libs/`, headless tests (`bash t.sh`), Python 3 standard library for textures.

**Spec:** `docs/superpowers/specs/2026-11-23-faction-tavern-design.md` (Bulgarian). Visual source of truth: `docs/mockups/08-faction-tavern.html` (read it as code; colours, proportions and copy below are taken from it).

## Global Constraints

- No Blizzard art, sound or font in the repo or zip. Client art is referenced only at runtime through `ns.Art`; every such reference has our own stand-in. Stand-in crests are our drawing (shield with crown / spiked circle), not copies of the emblems.
- An asset the check cannot confirm is missing: if `GetFileIDFromPath` or `C_Texture.GetAtlasInfo` is absent, everything of that kind is a stand-in. Never an empty or green square.
- Protocol `v = 1` stays. The only wire change is `HI` gaining `race` and `sex`. Theme and deck never reach the wire, the engines or the ledger.
- `theme` and `deck` are per-character db keys (`CHAR_KEYS`); default theme from `UnitFactionGroup("player")` (`"Horde"` -> `horde`, anything else -> `alliance`); default deck `faction`. A theme change applies after `ReloadUI` (button „Презареди сега“); a deck change is live.
- Fonts stay: headings Alegreya SC, text PT Sans, always via `Theme.setFont(fs, token, size)`. No Friz Quadrata, no stock WoW frame templates.
- Everything new lives inside the frames `ui/Resize.lua` scales (or follows them with `Resize.follow`).
- Corner index of a card (rank + suit) keeps its current size and position and draws above every new card layer.
- Coins (gold/silver/copper) only where the amount is real money; a fun Hold'em table keeps chips.
- Our textures: 32-bit uncompressed TGA, power-of-two sides, generated by a stdlib-only deterministic script in `tools/`. `tools/gen_textures.py` and every existing `media/*.tga` stay byte-identical; a new texture is appended LAST in its script's `TEXTURES`.
- Every new string in both `locale/bg.lua` and `locale/en.lua` (the key sets must match). To keep parallel tasks mergeable, insert a task's keys next to the related existing keys, never at the end of the file; same for `TavernGames.toc` lines and `tests/toc_test.lua` limits.
- No per-frame asset work: `Art.find` is memoized, portraits and cards are set only when their data changes.
- Tests: `bash t.sh` (all) or `bash t.sh tests/ui/x_test.lua`; 2053 pass before this plan and the suite stays green after every task. Style: `describe`/`it` with `eq`/`ok`/`raises`.
- Python: `"C:\Users\daxx\AppData\Local\Python\bin\python.exe"`.
- Commit after each task; never push.

## Review Focus

1. A client without `GetFileIDFromPath` / `C_Texture` at all: every surface must draw its stand-in and nothing may call a nil (tests: Task 1 `noArt`, Task 6 cards, Task 7 portraits).
2. `db.theme` / `db.deck` holding a value this version does not know (`"darkmoon"`, a number): the default is used, nothing raises, the saved value is left alone (Tasks 4, 5).
3. A hostile `HI`: `race` a 300-byte string or a table, `sex = 7`: stored as nil, never spliced into an atlas name, the plate falls back to the class icon (Tasks 3, 7).
4. A grouped player who is far away or offline: `SetPortraitTexture` would draw a question mark; the portrait must fall back to the race icon (Task 3 `unitOf` requires `UnitIsVisible`, Task 7).
5. A payment larger than the debt (credit) or a partial one: the toast's second line is „остават Z“ with the absolute balance, never „чиста“ and never a negative amount (Task 13).

### Task 13: The „Уредено“ toast (depends on: 1, 4, 10) — STRICT REVIEW (money)

**Background (read `core/Ledger.lua`, `core/LedgerNet.lua`, `core/LedgerView.lua`):** a payment is a `P` entry `{ f = payer, c = copper, how = "trade" | "mail" | "hand" }` written only by the creditor (its author). It is "confirmed" when it is a counted body of my store: new, not `un`. Live paths: my own `Net:make`, and `Net:take(e, from, true)` (a GUILD `LEV`, or a whispered one outside an exchange). The sync path is `Net:take(e, from, false)`.

**Interfaces — Produces:**
- Client event `"paid"` with `{ id = e.i, from = e.f, to = author, c = e.c, how = e.how, at = e.at }`, emitted when a `P` naming me (`author == L.me` or `e.f == L.me`) is (a) made by `Net:make` (not `"queued"`), or (b) taken with `live == true`, status `"new"`, body not `un`. Never for the sync path, a `"dup"`, a `"twin"`, another kind, or other people's payments.
- `Net:make(kind, fields, quiet)`: `quiet` suppresses the event; `Net:collide` remakes with `quiet = true` (the first body was announced already).
- `ns.SettleToast`: `FRESH = 300` (seconds: a `p.at` older than that against `client.env.epoch()` is ignored), `SECONDS = 6`, `MAX = 5` (queue; further ones are dropped), `seen` (id -> true), `queue`, `frame`, `title`, `sub`, `icon`.
- `SettleToast.text(client, p) -> title, sub`:
  - I am `p.to`: `settle.got` = „Уредено: %s ти плати %s“ / "Settled: %s paid you %s" (the payer's name in class colour, `W.money(p.c)`).
  - I am `p.from`: `settle.paid` = „Уредено: плати %s на %s“ / "Settled: you paid %s to %s".
  - `sub` = how + " · " + balance: `settle.how.trade` = „с размяна“ / "by trade", `settle.how.mail` = „по пощата“ / "by mail", `settle.how.hand` = „на ръка“ / "by hand"; with `net = View.net(View.of(client.ledger), me, other)`: `net == 0` -> `settle.clean` = „сметката ви е чиста“ / "your account is clear"; else `settle.left` = „остават %s“ / "%s left" with `W.money(math.abs(net))`.
- Showing: on `"paid"` the record is queued (unless seen or stale); on the next frame the head of the queue is shown for `SECONDS`, then the next; the balance is computed when a toast is shown (one `View.of` per toast, never per entry). `Art.play("settled")` once per toast. A click closes it.
- Frame: 360 x 64, `DIALOG` strata, at `TOP` of `UIParent`, 160 px down, `Resize.follow(f, "main")`; fill `0, 0, 0, 0.72`, a 1 px `brass` edge, a 44 px gold coin (`Art` coin or the `coins` cell) on the left, the title in the heading face 14 px `goldHi`, the sub line `dim`.
